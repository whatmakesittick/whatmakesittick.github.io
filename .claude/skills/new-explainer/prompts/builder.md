# Builder

You write the <slug> explainer package around the frozen contract: the entry, timeline, store, model, UI widgets, readouts, camera views, controller and bindings. A modeller builds the 3D assembly in another checkout and a writer writes the chapters and translations in a third; you never touch their files.

Main checkout, branch `feat/<slug>`. Read first: `ARCHITECTURE.md`, the spec at `<scratchpad>/<slug>-spec.md` (sections 2, 4 to 11 and 13 are yours), the facts sheet next to it (every readout number comes from it), the frozen files, and the newest explainer as the pattern for every file you write.

You own, under `explainers/<slug>/`: `explainer.json` (a placeholder `social.alt`; the coordinator replaces it with the writer's text), `src/index.ts`, `src/timeline.ts`, `src/model/**` except the frozen modules (plus `model/index.ts` re-exporting all of them), `src/state/**`, `src/ui/**`, `src/style.css`, `src/scene/index.ts`, `controller.ts`, `bindings.ts`, `cameraViews.ts`, `partInfo.ts`, placeholder `public/cover.webp` (932 × 699) and `public/social/og-image.png` (1200 × 630), and `scripts/cards/<slug>.html` from the newest card. Tests next to every pure module and DOM tests for the UI mounts.

The writer owns `chapters.html` and `locales/*.json`; both are excluded from git here, so keep temporary copies of `chapters.html` and all eight locale files (copies of the English) so the page runs and the build passes, and never `git add -f` them. Write them from the spec: the exact widget markup of section 10 and every key of section 11 with plain English placeholders that read sensibly. The key names, `data-readout` ids, `data-control` names and `data-action` and `data-value` pairs are the writer's contract; if you need a key the spec does not list, add it and name it in your report.

Implement: the timeline from section 2; the store from section 5 with chapter controls that reset like the newest explainer's and a `derived` module that builds the `AssemblyState` from the frozen model; the presets from section 6; the model modules from section 4 with tests on the facts sheet numbers; the dock choice and toggles with line icons; the gauge readouts; the chapter actions with `current`; one UI mount per chapter with `mountRangeWidget` and `mountLiveReadouts`; the scene glue: the controller builds the assembly through the frozen `createAssembly` (never import the placeholder directly), the camera views from section 14 (`CustomView` with `follow: true` for views that track the subject, `FramedView` on a region for fixed ones; resolve extra region ids from the layout constants in the controller), bindings with a double-buffered `AssemblyState`, `bindPresets` with `prepare` and `onView`, and a local `SCENE_OPTIONS` in `scene/index.ts` in one obvious block the coordinator swaps for the modeller's at integration.

Run the page with `npx vite --port 5180`, walk the six chapters with Playwright, confirm no console errors, readouts that change with the scrubber, chips and sliders that update their readouts, and the end of a one-shot run. Within your first hour, save a phone (390 × 844) screenshot of each chapter view with the placeholder boxes to `<scratchpad>/builder-shots/` and run `node e2e/tools/contact.ts` on them, so the coordinator can check the framings early.

Before your report also run `npm run lint`, `npm test` and `npm run build`. Report, besides the common parts: every key you added beyond the spec, every readout format, and the placeholder names each locale text receives.
